# 集合駅シミュレーター

東京都内の駅を対象に、参加者ごとの複数の出発候補駅と「時間・運賃」の重みから、集合駅のパレート解を比較する Python Web アプリです。集合日時から逆算します。リアルタイムの遅延・運行状況は取得しません。

## 起動

Python 3.11 以上を推奨します。

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python -m spot_simulator.server
```

http://127.0.0.1:8000 を開きます。標準ではローカルホストだけに公開します。公開サーバーとして運用する場合は HTTPS、アクセス制限、リクエスト制限が必要です。この開発サーバーをそのままインターネットに公開しないでください。

```sh
python -m unittest discover -s tests -v
```

## データの区別

- **実データ**: ODPT の時刻表・運賃データをサーバーから取得。都営はキー不要です。その他の対応事業者には無料の API キーが必要です。利用するデータの利用条件を確認してください。料金が発生する API や有料プランは使いません。
- **手入力**: 利用者が出典とともに与えた有限の経路集合。欠損運賃・欠損時間を推測しません。
- **架空サンプル**: 操作確認用の合成データ。実際の運賃・所要時間ではありません。明示的に選択した場合だけ読み込みます。

API キーはサーバー環境変数 `ODPT_API_KEY` に設定してください。チャット、ブラウザーの入力欄、ソースコード、Git のファイルには貼らないでください。`.env` は Git 対象外ですが、本アプリは自動で読み込みません。

ODPT は全国共通の経路検索 API ではありません。事業者ごとの対応データが必要です。出発・集合候補は対応事業者の東京都内の駅に限定します（通過区間まで東京都内に限定するものではありません）。東京都内の全駅・全私鉄を網羅できることを意味しません。運賃や列車時刻表が不足する経路、対象外事業者の経路を、仮の数値で補完しません。

ODPT 基本ライセンスやチャレンジ限定データの生データを、この公開リポジトリに含めません。チャレンジ限定データの自動利用も行いません。API が未設定・失敗した際に架空サンプルへ自動切替しません。

参照:
- [ODPT 開発者サイト](https://developer.odpt.org/)
- [ODPT データ基本ライセンス](https://developer.odpt.org/terms/data_basic_license.html)
- [東京メトロ運賃](https://ckan.odpt.org/dataset/r_fare-tokyometro)

## 最適化モデル

入力された候補駅 s について、各参加者 i が経路 r を一つ選択する 0–1 整数線形計画（MILP）です。出発駅を複数入力した場合は「どれか一つから出発できる」という意味です。全員がすべての出発駅から移動する意味ではありません。自宅から出発駅までのアクセス時間は含みません。

各参加者の時間重み α_i と運賃重み β_i は非負、α_i + β_i = 1。目的関数は次の **2 つ** です。

- T = Σ_i α_i × 所要時間_i / S_T
- F = Σ_i β_i × 運賃_i / S_F

S_T は既定60分、S_F は既定1,000円の固定正規化基準。全候補に同じ正の基準を使い、表示の尺度を揃えます。候補の最大・最小による正規化ではありません。重みは小数点以下3桁まで対応します。

実データの時間評価は **集合までの所要時間（早着時の待ち時間を含む）**、つまり集合日時−出発日時です。実移動時間・集合駅での早着待ちを別項目で示します。乗換時間はすでに所要時間に含まれ、二重加算しません。乗換徒歩時間は時刻表だけでは判定できないため、推定値を使う場合は明示します。

T と F は参加者の好みを反映した評価値です。単純な合計分・合計円とは異なります。画面には評価値と実単位の合計を両方示します。個人間の公平性を保証する目的関数ではありません。

### パレート解を取りこぼさない方法

各集合駅について、運賃目的の上限 ε の下で時間目的を最小化し、その最小時間の下で運賃目的を最小化します。次の ε は見つかった整数運賃目的値−1とし、実行可能解がなくなるまで繰り返します。最後に駅をまたいで厳密に支配された解を除外します。正の重み付き和を繰り返す方法では見つからない非凸のパレート点も対象です。

時間は整数秒、運賃は整数円、重みは1/1000単位で計算し、ε の減少量を定義します。ソルバーは SciPy/HiGHS の MILP を用い、整数許容誤差を厳しく設定した上で整数解・全目的制約を再検証します。単純な連続 LP は参加者が複数経路に分裂する解を許すため用いません。

同じ駅・同じ評価値を持つ経路組合せは代表1件を返します。同じ評価値を持つ異なる駅は保持します。経路が欠ける参加者がいる駅は除外理由を返します。

**最適性の範囲**: 有限の入力経路・候補駅の範囲に限ります。時刻表探索の時間範囲・乗換上限・事業者範囲の外までは保証しません。ソルバーの時間上限や点数上限に達した場合、完全な解と偽って部分結果を返すことはせず、エラーを返します。

## API

`GET /api/status`: 実データ接続・対応範囲の状態。

`POST /api/optimize`: JSON。参加者最大12人、各出発候補最大10駅、集合候補最大500駅、入力経路最大10,000件。

```json
{
  "mode": "manual",
  "meeting_at": "2026-10-20T18:00:00+09:00",
  "participants": [{"id":"p1","name":"参加者1","origins":["出発駅A","出発駅B"],"time_weight":0.5,"fare_weight":0.5}],
  "candidate_stations": ["集合駅C"],
  "time_scale_minutes": 60,
  "fare_scale_yen": 1000,
  "routes": [{"participant_id":"p1","origin":"出発駅A","destination":"集合駅C","duration_minutes":30,"fare_yen":300,"transfer_minutes":5,"source":"説明用の架空値"}]
}
```

`mode: live` では provider が経路集合を取得します。集合候補を空にすると、選択した事業者の東京都内の対象駅を自動探索します。明示した場合はその候補だけで比較します。`mode: demo` は架空データと明示します。返却値は `solutions`、`excluded_stations`、`warnings`、`metadata`。手入力モードでは入力された時刻・運賃の正しさを外部検証しません。

## 保護と制約

- 個人情報・入力駅情報の永続保存なし。外部データ取得時に、検索対象の駅等がデータ提供元へ送信される場合があります。
- 秘密情報を応答に含めず、同一オリジンのみ受け付けます。
- HTML には利用者の入力をテキストとして表示します。
- 本ツールの結果は参考情報です。実際の移動前に鉄道事業者の最新案内を確認してください。

詳しい事業者別の対応状況は [データ対応表](docs/data-coverage.md) を参照してください。都営は公開 API のためキー不要で利用でき、その他の対応事業者は無料登録キーが必要です。

## 駅時刻表からの補完（任意）

画面の「列車IDが一致する駅時刻表から経路を補完する」を有効にすると、列車時刻表で不足する便について、駅時刻表の安定した列車IDと路線の駅順を使う補完を試みます。API では `use_station_timetable_fallback: true` を指定します。

- 発車時刻を到着時刻の代用にするという前提です。結果の出典・経路にも補完を明示します。
- 単に次に発車する列車を同じ列車とみなすことはしません。
- 列車ID、適用日、方向・駅順などを確認できない便は使用しません。
- 終着駅に発車時刻が載っていなければ、その駅の到着時刻を捏造しません。
- この機能でデータの利用条件や対応事業者を自動的に拡大することはありません。

時刻表・運賃の公開日や有効期限が不足している場合があります。取得に成功したことは、現在または未来のダイヤ・運賃が正しいという保証にはなりません。画面に表示する元データの日付・注意事項を確認し、移動前には事業者の最新情報を確認してください。

## 駅の識別と初回検索

同名でも別の駅を誤って一つの集合場所にしないため、実データの集合候補は路線別の ODPT 駅IDで識別します。駅候補の補完欄には駅名・事業者・路線を表示します。複数の駅IDに対応する名前を入力した場合は、明確な駅IDを選ぶよう案内します。たとえば、つくばエクスプレスの浅草駅と都営の浅草駅を名前だけで統合しません。同一駅名の別路線ホーム間の移動を、集合地点で自動的にゼロ分とみなすこともしません。

初回は時刻表・運賃の取得に1〜2分以上かかることがあります。取得済みデータはサーバーのメモリー内で時間単位にキャッシュします。探索の計算上限に達した場合は、完全な結果のように部分結果を返さずエラーを示します。
